# たばコン 仕様書

## 1. 基本情報

- ゲーム名: たばコン
- game_slug: `tabakon`
- 公開URL: `https://chameleonjp.codeberg.page/tabakon/`
- 形式: `index.html` 1ファイルで完結するスマホ向けブラウザゲーム
- 表示Canvas論理座標: 320×480
- 内部ゲーム世界: 320×960
- ステージ設計・地形グリッド: 48×144

## 2. ゲーム目的

Canvas上の砂を指で削り、30個の🚬を重力で流して🦊の回収ゾーンへ届ける。20個届けると、その到達時点の残り時間とスコア対象を固定し、短い成功演出後に終了する。制限時間は60秒。

上手いプレイの差は、高得点の色を多く届けること、短時間で20個届けること、失う🚬を減らすことで付く。

## 3. 画面状態

- `HOME`
- `RULE`
- `READY`
- `PLAYING`
- `RESULT`
- `ERROR`

`READY`では3、2、1のカウントを行い、制限時間と物理は進めない。`PLAYING`開始時に60秒の絶対期限を設定する。`RESULT`では`stopLoop()`でゲームループを止める。

## 4. Canvas・世界座標・カメラ

`setupCanvasResolution()`で`devicePixelRatio`に応じてCanvas内部解像度を上げるが、ゲーム内の論理座標は320×480のまま扱う。

世界内の砂、壁、🚬、仕掛け、トラップ、ゴールは320×960の世界座標で保持する。左端24pxの縦バーで`cameraY`を操作し、`screenToWorld()`で画面入力を世界座標へ変換する。Canvas要素自体を960pxの高さでは表示しない。

## 5. 入力

タッチ開始位置で操作を固定する。

- 左端24px: カメラ操作
- それ以外: 砂削り
- 砂削り開始後に左バーへ入ってもカメラ操作へ切り替えない
- カメラ操作開始後に盤面へ入っても砂を削らない
- `pendingClear`中は結果へ影響する砂削りを受け付けない

現在の掘削半径は20pxであり、実機評価では広すぎると判定されている。半径縮小と入力バッチ化は、平面振動修正の実機合格後に行うコアゲーム性改修のP0項目とする。

## 6. 砂

砂と固定壁は48×144の`Uint8Array`グリッドで管理する。プレイヤーが砂を削った周辺だけ`settleSandAround()`で局所崩落させる。

- 真下が空なら1セル下へ移動
- 真下が埋まり、斜め下へ移動できる場合は斜めへ崩落
- 世界全体を毎フレーム動かさない
- 固定壁は削らない
- 砂解像度の細分化と、砂が🚬・ゴール・仕掛けへ入り込む保護は後続改修で扱う

砂を実際に削れた場合、近距離で休止中の🚬を起こし、進展なし終了の猶予を更新する。

## 7. 🚬の種類

| 種類 | 点数 | 重力・挙動 | 衝突質量 |
| --- | ---: | --- | ---: |
| 白っぽい🚬 | 1000 | 標準 | 1.00 |
| 赤い🚬 | 1500 | 重く、跳ねにくく、横へ転がりにくい | 1.25 |
| 青い🚬 | 1300 | 軽く、跳ねやすく、仕掛けの影響を受けやすい | 0.80 |
| 黒い🚬 | 1700 | 高得点。危険ゾーンへ近づくと失いやすい | 1.10 |

質量は🚬同士の衝突にだけ使い、既存の重力・反発・横減速の個性は維持する。

## 8. PR3ボール物理契約

### 8-1. 固定間隔更新

```js
const PHYSICS_DT = 1 / 120;
const MAX_PHYSICS_STEPS = 6;
const MAX_ACCUMULATED_TIME = PHYSICS_DT * MAX_PHYSICS_STEPS;
```

- `requestAnimationFrame`は描画入口として維持
- 表示1回につき最大6回まで物理更新
- 復帰直後などの過大な遅れは切り捨て
- 制限時間はPR2の絶対期限方式を維持
- 成功演出中は物理蓄積値を破棄し、物理を進めない

### 8-2. 半径

```js
const BALL_RADIUS = 8;
const BALL_DRAW_RADIUS = 9;
const BALL_SHADOW_RADIUS = 10;
```

- 地形、壁、仕掛け、トラップ、ゴール、🚬同士の判定は`BALL_RADIUS`を基準にする
- 色付き本体と物理判定の差は1px
- 影は判定に使わない
- 個体生成時の`r`直書きはせず`BALL_RADIUS`を使う

### 8-3. 初期配置

1クラスタ10個を5列×2行で配置する。横・縦間隔は17pxとし、直径16pxの🚬が初期状態で重ならないようにする。

### 8-4. 地形衝突・平面静止・すり抜け防止

円と周辺の全接触セルから、食い込み量で重み付けした接触法線を合成する。単一の最深セルだけを採用せず、セル境界で法線が左右へ切り替わる振動を抑える。

接地法線は連続フレームで混合し、急な法線切替を抑える。平面は`abs(normalX) <= 0.12 && normalY < -0.95`で判定する。

```js
const TERRAIN_BOUNCE_MIN_SPEED = 36;
const GROUND_STOP_SPEED = 22;
const STATIC_FRICTION_SPEED = 12;
const FLAT_GROUND_NORMAL_X = 0.12;
const GROUND_NORMAL_BLEND = 0.24;
const GROUND_STABLE_DELAY = 0.18;
```

- 法線方向の衝突速度が36px/秒未満なら反発係数を0にして速度を接触面へ吸収する
- 平面上で横速度が12px/秒以下なら0へ吸着する
- 平面では斜面加速やゴール方向への人工ナッジを一切行わない
- 斜面では接触法線へ投影した重力の横成分だけを使う
- 1回の固定物理更新で移動距離が`BALL_RADIUS * 0.5`を超える場合、最大4分割する
- 速度上限は900px/秒

### 8-5. 🚬同士の衝突

activeな組み合わせを全組判定し、各固定物理更新で2回解決する。

- 食い込みを質量の逆数比で分離
- 接近中だけ法線方向の反発を付与
- 相対接近速度が18px/秒未満なら反発係数を0にする
- 接線方向へ弱い摩擦を付与
- 同一座標の場合はID由来の固定方向で分離
- ランダムな横揺れを入れない
- 両方が休止中で重なり0.5px以下なら微小位置補正を行わない
- 重なり量だけでは休止解除しない
- 相対接近速度8px/秒以上、または衝撃量12以上の場合だけ衝突で起こす

```text
位置補正率: 0.8
許容重なり: 0.1px
衝突解決: 2回/固定物理更新
```

### 8-6. 休止と復帰

平面接地が0.18秒以上安定し、仕掛け非接触、速度4px/秒未満の状態が0.35秒続いた🚬は休止し、速度を0にする。

復帰条件:

- 近くの砂を削った
- 他の🚬から相対速度8px/秒以上または衝撃量12以上の接触を受けた
- バー、ゲート、ローターへ接触した
- 下側3点の支持地形が失われた

休止中の🚬同士は微小な重なりだけで互いを起こさない。休止中でもゴール、危険ゾーン、最下部、終了判定の対象から外さない。

### 8-7. バーとローター

バーは初回の強い上面衝突だけ反発させる。低速接触は`vy=0`へ寄せ、バー速度の一部を横速度へ伝える。同一接触中に毎固定更新で反発を追加しない。

ローターは接触位置、回転速度、回転方向に応じた接線速度を使う。同一接触中の連続加速を避けるため、50msの接触待ち時間を設ける。接触中の食い込み解消自体は継続する。

## 9. ステージ

10種類の名称を持つが、現時点では`makeStage(name, shortName, variant)`による共通生成型。共通の砂・壁・導線を基に、ゴール位置、危険側、一部壁、トラップ、バー、ローターを変えている。

選択は`STAGES[Math.floor(Math.random() * STAGES.length)]`であり、同じステージが連続する可能性がある。

実機評価では、中央を縦に掘るだけで成功でき、ステージ差・ルート判断・戦略性が不足していると判定されている。現状のステージは完成仕様ではなく、次のコアゲーム性再設計を必須とする。

- 3クラスタを独立した初期室へ分ける
- 1室だけの解放では20個へ届かない
- 中央一直線ルートを固定壁とオフセット開口で遮断する
- 上層・中上層・中下層・下層に意思決定を置く
- 安全路、短距離危険路、高得点路を分ける
- ステージ1を先に完成させてから残り9ステージを個別化する

## 10. 終了条件

- 20個到達
- 60秒経過
- リタイア
- activeな🚬が0
- `delivered + activeCount < NEED`
- 全active🚬がゴールより下
- 全active🚬が2秒以上停止し、意味のある移動と実際に砂を削れた操作がどちらも8秒以上ない

20個目が届いた瞬間に残り時間、到達数、スコア対象を固定する。成功演出中は砂、仕掛け、物理、追加到達、喪失、残り時間を進めない。

公開上の`reason`は`clear` / `fail` / `retire`。内部原因は`endCause`で保持する。

## 11. タイマーとスコア

残り時間は`performance.now()`基準と`Date.now()`基準の絶対期限から算出し、短い方を採用する。処理落ちやバックグラウンド移動で残り時間を延長しない。

```text
配達スコア
= 届けた🚬の点数合計
+ floor(残りミリ秒 / 10)
- 失った数 × 300
- リタイア時 5000
```

失敗、リタイア、マイナススコアも送信する。

## 12. ランキング

- game_slug: `tabakon`

## 13. 結果・シェア

結果画面には成功・失敗・リタイア、配達スコア、届けた数、失った数、残り時間、ステージ、スコア内訳、ランキングを表示する。

失敗、リタイア、またはマイナススコアでは指定済みコメントを完全一致で表示する。ホームと結果のシェア文末尾には公開URLを入れる。

## 15. 現在のP0ブロッカー

PR #24はDraftかつマージ禁止とする。次を実機で解消するまでPR3完了扱いにしない。

- 平面上の目視可能な振動が1秒以上続かないこと
- 中央1本掘りだけでは20個へ到達できないこと
- 掘削半径が操作に対して過剰でないこと
- スクロールバーが初見で上下操作と認識できること
- 最低2回以上のルート判断が必要なこと
- 10ステージに戦略上の差があること

平面振動については、低速反発停止、静止摩擦、接触法線合成・平滑化、人工ナッジ削除、重なりだけによる休止解除の廃止を実装済みであり、実機再確認待ちとする。
